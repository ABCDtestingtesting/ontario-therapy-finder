PT Weekly Competition Monitor — Mac

Double-click Run.command. Terminal only; no browser opens. Python 3.9+ with Toronto zone data required. The first run requests optional API keys and a written Psychology Today permission reference; Configure.command changes them. The program performs no direct PT automation without permission. Use authorized free/hard-capped API accounts; Brave may require billing details. Never enable paid overages. Each configured discovery source uses 120 requests per survey, local monthly cap 600, which is not a provider billing guarantee. Search results are indexed leads only, not verified advertisers. Brave receives an FSA postal-location hint on the second query; whether the provider honors it is recorded where returned. Tavily varies query text, not request origin. PT uses direct FSA directory URLs, no fake location or proxy rotation. There is no Google or Bing adapter in this version.

Reports: ~/Library/Application Support/PT Weekly Competition/YYYY-MM-DD. Dates use Toronto Monday-to-Sunday weeks. Running again on the same day resumes completed observations; another day creates a new survey. Blocked sources stop for that run; no invented zeros. Daily results are deduplicated within each FSA; separate counts and per-capita CSVs are written. Count agreement is a public visibility observation, not a certified internal competitor count. Zero is only accepted with an explicit zero on the verified directory. Exit status 3 indicates incomplete PT coverage. Configure and run on three different days for weekly variability. Never publish an exact ranking from these observations. Source hashes are retained, no full page copies or names. Provider permissions and network access are required for actual live tests.
